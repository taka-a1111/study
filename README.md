## ver7.4（キャラは「出会って」「やりきって」ゲット）

## ver7.2（3つの学習モード）

公文式のカリキュラム（教材・ステップ・標準完成時間・訂正）はそのままに、外側の「進め方」を3つから選べるようにした。学習画面の上部で切り替える。学習者ごとに保存される。

### 1. プリント（これまでどおり）
ステップ内の5枚の進捗と玉を表示する、従来の画面。

### 2. すごろく（マスを すすむ）
30マスのワールドを、プリント1枚ごとに1マス進む。マップ画面で現在地（自分のアイコン）と、これから来るイベントが見える。
- ★ たまボーナス（5・15・25マス）：おまけの玉
- 🎮 ミニゲーム（7・14・21・28マス）：3択バブル5問・30秒。全問正解でキャラ1回
- 🎁 プレゼント（10・20マス）：キャラ1回
- 🏁 ゴール（30マス）：ワールドクリア、キャラ1回、次のワールドへ

### 3. ぼうけん（なぞとき）
6章のストーリー。プリント1枚ごとに場面が1つ進み、場面によってヒントが手に入る。5枚で章の終わりに「なぞとき」が出て、集めたヒントをもとに3択から選ぶ。
- 正解：章クリア、キャラ1回、次の章へ
- 不正解：ヒントを読み直して何度でも挑戦できる（罰なし）
- 6章を終えると2周目に入る（周回数を表示）

章の一覧：ふしぎな もりの いりぐち／やまの どうくつ／うみべの まち／そらの しま／ほしの さばく／ゆめの おしろ。各章に3つのヒントがあり、選択肢はヒントを合わせれば一意に決まるように作ってある。

### 共通
- どのモードでも解くプリントは同じ。玉・じこベスト・修了証・キャラ（5枚に1回）はそのまま
- 結果画面の「つぎの プリントへ」を押すとイベント（マス・場面・なぞとき）が挟まり、閉じると次のプリントへ進む
- すごろくの位置とぼうけんの進行は端末間で同期される（進んでいるほうを採用）
- 学習者のリセットで初期化される

### 玉の見た目を統一
大玉の輪と輝きを外し、ふつうの玉と同じ質感で少し大きい7つ星にした。ラベルは玉の下の行に分けて、途中で改行しても崩れないようにした。

## ver7.0

### 音声入力のバグ修正
「入らない」「2回言うと両方の数字が入る」の原因は、途中経過（interim）と確定（final）の扱いにあった。

- 途中経過は認識が進むにつれて内容が伸びる（「5」→「50」）。これを1文字ずつ追加していたため「550」のようにくっついていた。
- 修正：音声の結果は追加ではなく置きかえにした。「50」と言えば必ず50になる。言い直しても前の数字は残らない。
- 同じ発話で同じ内容が届いた場合（途中経過と確定の重複）は無視する。これで二重入力がなくなる。
- マイクの権限が拒否されている場合にエラーを出して停止するようにした（無言で止まっていた）。

### 手打ちでも即座に丸
キーパッドで打った場合も、正解になった時点で「こたえる」を押さずに丸がつくようにした（手書き・音声と同じ動き）。

途中の数字で誤って送信されないことを確認済み。答え12に対して「1」では進まず「12」で進む、答え100に対して「1」「10」では進まず「100」で進む、あまりのあるわり算は商と余りが両方そろってから進む。

## ver6.9（おかわりと大玉）

1日の目標を達成したあとも、やった分だけ報われるようにした。玉が増えすぎない工夫として、目標枚数ぶんたまると1つの大玉にまとまる。

- 目標（既定5枚）までは、これまでどおり星入りの玉が並ぶ
- それを超えると仕切り線の右に「おかわりの玉」が増える
- おかわりが目標枚数ぶんたまると、それらが金の輪をまとった大玉1つに置き換わる（5枚＝大玉1つ）
- 大玉は4つまで並べ、それ以上は「×9」のように数で表示するので、何十枚やっても表示は崩れない
- ラベルは「あと 2つ」→「ぜんぶ そろった！」→「おかわり 9まい（大玉 1）」と変化する

### お祝いの追加
大玉ができた瞬間（目標＋5枚、＋10枚…）にも全画面のお祝いが出る。タイトルは「おかわり たっせい！」、玉は大玉が浮かび上がる。1日1回の通常のお祝いとは別枠で、何度でも出る。

### 結果画面
おかわりのときは「おかわりの たま！」、大玉ができたときは「大玉を てにいれた！」と表示し、下の一覧にも大玉が並ぶ。

## ver6.7（保護者ロックの整理）

指紋・パスコード・計算がそれぞれ別の場所にあって切り替えが分かりにくかったため、1か所にまとめた。

保護者メニュー → 保護者ロック → 「保護者メニューの ひらき方」で3つから選ぶ。

1. 計算の 答えを 入れる（既定）
2. パスコード
3. 指紋・顔

選んだものに応じて、下に必要な設定だけが出る。計算を選ぶと、登録済みの指紋は自動で解除される。パスコード未設定・指紋未登録のまま選んだ場合は計算のままにしておく（締め出し防止）。

### 計算のむずかしさを追加
子どもがかけ算を覚えるとロックとして機能しなくなるため、3段階から選べるようにした。

- 2けた × 1けた（れい 23 × 7）
- 2けた × 2けた（れい 47 × 23）
- 3けた × 2けた（れい 268 × 34）

## ver6.6（保護者パスコード）

Androidの生体認証は、指紋が読めないときに端末の画面ロック（パターン・PIN）へフォールバックする。子どもがパターンを知っている場合、指紋認証は保護者ロックとして機能しない。この指摘を受けて、独立したパスコードを追加した。

- 保護者メニューに「保護者パスコード」を追加。4〜8けたの数字を決めると、以降は保護者メニューがそのパスコードでしか開かなくなる（かけ算は出ない）。
- 入力は●で伏せ字表示。5回まちがえると学習画面に戻る。
- パスコードはそのまま保存せず、ランダムな塩を付けたSHA-256ハッシュにして保存する。
- クラウド同期に含まれるので、もう1台の端末でも同じパスコードになる。
- 「パスコードを やめる」でかけ算のロックに戻せる。
- 生体認証の設定欄に、画面ロックへフォールバックする旨の注意書きを赤字で追加した。

### パスコードを忘れたとき
保護者メニューに入れなくなる。もう1台の端末から変更するか、ブラウザのサイトデータを削除してから同じアカウントでログインし直せば、学習記録はクラウドから復元される。

## ver6.5（バグ修正）

ver6.4で入れた「線を保持してそのつど読み直す」方式が、実際には動いていなかった。画面の再描画（draw）のたびに手書き面を消していたため、1けた書くごとに線が消え、2けた以上が正しく読めず、自動送信も成立しない状態だった。

- 手書き面を消すのは「問題が変わったとき」だけに限定した（問題ごとのキーを持たせて判定）
- 自動送信の直後にも確実に消す
- 診断テストの画面にも同じ処理を入れた

これにより、手書きで書いた答えが合っていれば「こたえる」を押さずに丸がついて次へ進む。まちがっているときは止まるので書きなおせる。

## ver6.4（手書きの反映を速く）

書いてから数字が入るまでの待ちを 0.85秒 → 0.24秒 に短縮した。

### やり方を変えた
これまでは「一定時間待つ → 認識 → 数字を追加 → キャンバスを消す」だった。待ち時間を短くすると、4や5のように2画で書く数字が途中で確定してしまうため長めに待つ必要があった。

新しい方式では、書いた線を消さずに保持し、そのつど全体を読み直して答えを上書きする。途中で誤って確定しても、続きを書けばすぐ正しい値に更新されるため、短い待ち時間で問題ない。

- 線を1本引くたびに0.24秒後に全体を読み直す
- 認識にかかる時間は1〜3けたで3〜10ミリ秒（実測）なので、体感はほぼ即時
- 正解になった時点で自動送信されるので、書き終わるとそのまま次の問題へ進む

### ボタンを変更
- 「1つ もどす」…直前の線だけ取り消す。書き損じの修正が楽になった
- 「ぜんぶ けす」…全部消してやり直す

- ひらがなの数（じゅうご、にじゅうよん、せんにひゃくさんじゅうよん）にも対応した
- 24パターンのテストで全件、意図どおりに判定することを確認済み

## ver5.9（リセット）

保護者メニューに「はじめから やりなおす」を追加した。学習者を選んで2種類のリセットができる。

- 進度だけ もどす：教材の位置を6Aのさいしょに戻す。りれき・グラフはそのまま残る。
- きろくも ぜんぶ 消す：りれき・じこベスト・しゅうりょうしょう・メッセージも含めて消す。テストで進めたぶんを消したいときはこちら。

### 同期との整合
リセットは端末ごとに行われるため、単純な統合ではクラウド側の古い記録が復活してしまう。これを防ぐため、消した時刻（wipedAt）を学習者ごとに記録し、統合時に次の扱いをする。

- その時刻より前の履歴・メッセージは復活させない
- じこベストと修了証も、相手側の最終活動がリセットより古ければ取りこまない
- リセット自体を「活動」として扱い、進度はリセットのほうが新しければリセット後の状態を採用する
- リセット後に新しく学習したぶんは通常どおり残る

## ver5.5（手書きで複数けたをまとめて入力）

- 1文字ずつしか入らなかった手書き入力を、まとめ書きに対応させた。「121」と続けて書くと3けたが一度に入る。
- 処理の流れ
  1. 描いた線を連結成分（つながっているかたまり）に分解する
  2. 4や5のように2画に分かれる数字を、横方向の重なりが34%を超える場合に1文字として結合する
  3. 左から順に並べ、それぞれをMNISTと同じ形（長辺20px・重心中央の28px枠）に整えて認識する
- 横に長い線はマイナス、下のほうの小さな点は小数点として扱う（その問題で必要なときだけ）。
- 認識の待ち時間を0.62秒から0.85秒に延長（複数けたを書き終えるまで待つため）。
- 検証：MNISTの数字を並べた2〜3けたの画像120件で98.3%が完全一致。文字の間隔を-8px（軽く接触）から90pxまで変えても93%を維持。

## ver5.2（家族で共有するクラウド同期）

夫婦それぞれの端末で同じ進度を見られるようにした。

### 使い方
保護者メニューの「クラウド同期（家族で共有）」で、メールとパスワードを入れて「はじめて（アカウントを作る）」。もう1台の端末では同じメールとパスワードで「ログイン」する。以降は自動で同期される。

- プリントを1枚おえるたびに自動保存
- アプリを開くたびに自動で取りこみ
- 手動の「いま すぐ 同期する」「クラウドの 記録を 取りこむ」も用意
- ログアウトしても端末の記録は残る
- 2回目以降のロック解除は指紋認証がそのまま使える（パスワード入力は初回だけ）

### 統合のしかた
同じ子を別々の端末で進めた場合に備え、単純な上書きではなく統合する。
- 履歴：両方を合わせて重複（同じ時刻・同じ教材）を除去し、時系列に並べる
- 進度（教材・枚数）：最後に学習した時刻が新しいほうを採用
- 学習者：片方にしかいない子はそのまま追加
- 例題の既読フラグ：両方の和をとる

### 技術
- Supabase の既存プロジェクト（helm）に kumon_state テーブルを1つ追加。user_id 主キー、payload jsonb、updated_at
- RLS を有効にし、自分の行だけ読み書きできるポリシーを4つ設定
- supabase-js は使わず fetch で REST / Auth を直接叩いている（CDN依存をなくしオフライン動作を保つため）
- アクセストークンが切れたら refresh_token で自動更新

- iOSなど beforeinstallprompt が使えない環境では、同じモーダル内に共有→ホーム画面に追加の手順を表示する。
- インストール完了後は案内もバナーも出さない。

## ver3.4 の修正（1タップインストール）

- beforeinstallprompt を head 内の先行スクリプトで捕まえるようにした。本体スクリプトの実行前にイベントが飛ぶと取り逃してインストールボタンが手順表示になってしまうため。
- manifest に id・display_override・categories・prefer_related_applications を追加し、Chromeのインストール要件を満たす形に整えた。
- インストールがキャンセルされたときだけ手順モーダルを出すようにし、モーダル内にも直接インストールボタンを置いた。

補足：ブラウザの仕様上、確認ダイアログなしで勝手にインストールすることはできない。Android/Chromeではボタン1つ→OSダイアログで「インストール」の2タップが最短。iOSのSafariはインストールAPI自体が提供されていないため、共有→ホーム画面に追加の手順表示になる。

## ver3.3 の追加

- ホーム画面に「アプリとして つかう」バナーを追加。Android/Chromeでは1タップでインストール、iOSやその他のブラウザでは追加手順を表示する。
- 保護者メニューに「アプリとして入れる」「リンクを共有する」を追加。navigator.share対応端末では共有シートが開き、非対応ならリンクをコピーする。
- すでにアプリとして起動している場合（display-mode: standalone）はバナーを出さない。バナーは×で非表示にでき、以降は保護者メニューから入れられる。

## ver3.2 の修正

- 保護者ゲートをアプリ内テンキーに変更。OSのキーボードが出ないので、画面が押し上げられて入力欄が隠れる問題を解消した。
- 自動アップデートを実装。version.json のビルド番号を起動時とアプリ復帰時に確認し、新しければキャッシュを消して自動で読み込み直す。Service Worker もネットワーク優先＋skipWaiting／clients.claim に整理した。

## ver3.1 の修正

- アイコンを作り直し。maskable用（Androidで円形に切り抜かれるもの）は中身を中央40%に収め、端が欠けないようにした。通常用は角丸の全面塗り。
- Androidの戻るジェスチャー・戻るボタンで、アプリを閉じずに前の画面へ戻るようにした。
  - プリント中の戻るは「やめますか」の確認を出す（採点中は無視）
  - まるつけ・けっか・れいだいからの戻るは学習画面へ
  - 保護者メニューは戻る履歴から除外（子どもが戻るで入り込めない）
  - 学習画面での戻るは1回目は何もせず、もう一度でアプリ終了

## ver2.0 からの変更

1. 学習者の登録（複数人）
   名前とアイコンを登録し、進度・記録を人ごとに保存。ホーム右上の「きりかえ」で切替。

2. カリキュラムを147ステップに細分化
   公文式の教材番号（C 11-20 など）にならった刻みに変更。1ステップ＝5枚、全735枚。
   例：C教材は「Bまでの復習／3までの九九／5までの九九／7までの九九／9までの九九／九九ぜんぶ／2けた×1けたの1〜3／3けた×1けた／九九のぎゃくの1・2／あまりのあるわり算の1・2／2けた÷1けたの1・2／3けた÷1けたの1・2／わり算のまとめ／Cのまとめ」の20ステップ。

3. 1問ごとの採点（既定オン）
   答えると ○ が出る。まちがえたら × と正しい答えをその場で表示。

4. まるつけ画面を一覧に変更
   ○が並ぶだけでなく、式・自分の答え・正しい答え（緑）を1問ずつ表示。

5. 保護者メニューにロック
   入るときに2けた×1けたのかけ算に答える必要がある。教材位置の変更にも同じロック。

6. 音声入力
   キーパッドのマイクボタンで答えを声で入力（Chrome等、Web Speech API対応ブラウザ）。
   「じゅうご」「15」「マイナス3」に対応。保護者メニューでオフにできる。

7. 診断テストは日々の学習と分離
   起動時は必ず学習画面。診断テストは登録時と保護者メニューからのみ。

8. デザイン刷新
   「こたえる」ボタンのはみ出しを修正。ボトムナビ4つ、余白と文字サイズを整理。

## 公文式のノウハウ → 実装

| 原則 | 実装 |
|---|---|
| ちょうどの学習 | 学年選択・診断テストとも、解けるところより手前を開始位置にする |
| スモールステップ | 147ステップ、1ステップ5枚 |
| 自学自習 | 各ステップ冒頭に例題（実際に出る問題と答えを自動生成） |
| 標準完成時間 | ステップごとにx秒〜y秒。x以下＝合格／x〜y＝合格／y超＝くり返し |
| 100点にして終わる | 全問終了後に一覧で採点、間違いは正解するまで再出題。訂正時間は計測外 |
| 反復 | 不合格なら同じプリント。3回続いたらステップの1枚目に戻る |
| 毎日一定量 | 1日のまい数、連続日数 |
| 学年を越えて進む | 進行は教材番号のみ |
| 計算に絞る | 文章題・図形は扱わない |
